# ai-kit

Бэкенд-стартер методологии: канон, реестр правил, шаблоны документов, профиль, интервью, генератор и валидатор для бэкенд-части проекта. Frontend, mobile и desktop не входят осознанно. Стек и домен в ядро не входят — они живут в адаптере и профиле.

Статус: рабочая версия. План разработки и открытые вопросы ведутся вне репозитория; в поставку входят только контракты, шаблоны и код.

## Установка

```text
python -m pip install -e .
ai-kit --help
```

После установки команды работают из любого каталога. Альтернатива без установки — `PYTHONPATH` на каталог репозитория и `python -m ai_kit.<команда>`.

Обычный `pip install .` не поддерживается: шаблоны, канон и банк вопросов лежат вне пакета. Нужна editable-установка `pip install -e .`; иначе генератор не найдёт ресурсы.

В примерах ниже интерпретатор называется `python`; если в системе он доступен как `python3`, замени имя команды. После установки доступна консольная команда `ai-kit`.

Все файлы — UTF-8 без BOM. Терминал должен работать в UTF-8; если символы отображаются искажённо, переключи кодировку терминала.

## Запуск агента

Полный промпт: [docs/agent-prompt.md](./docs/agent-prompt.md).

Скопируй в агента, запущенного в каталоге проекта:

```text
Прочитай <путь к ai-kit>/docs/agent-prompt.md и выполни его целиком.
Стартер — тот же путь без docs/agent-prompt.md.
Проект — текущий каталог.
```

Готовый текст с уже подставленным путём:

```text
python -m ai_kit.prompt
```

Команда запускается из каталога проекта, как и остальные команды набора.

## Каталог документов

Путь задаётся `docs.dir` в профиле. По умолчанию `.project`; для новых проектов рекомендуется `.ai`.

| Каталог | Когда |
|---|---|
| `.ai` | документы для агента и человека отдельно от публичного `docs/`; короткая и узнаваемая конвенция |
| `docs/ai` | если скрытый каталог плохо виден в IDE или поиске |
| `.project` | текущий дефолт; нейтрально, но не говорит о назначении |
| `.agent` | не используем: читается как конфигурация агента, а не документация |

Скрытый каталог хуже заметен: ссылки из `README.md` и `AGENTS.md` обязательны. Если `docs/` собирается в сайт, `.ai` не смешивается с публикацией. Смена каталога — `docs.dir` профиля и `init --refresh`.

## Область применения

Стартер сделан для **бэкенд-части проекта**: API, сервисы, фоновые задания, хранилища. Ядро — канон, маршрут, ревью, интервью, генератор, проверки — не зависит от стека; форма профиля и шаблонов — бэкендовая.

Что входит:

- бэкенд-часть проекта с исходниками, публичными входами (HTTP, CLI, события), хранилищами, миграциями и моделью доступа;
- бэкенд в отдельном репозитории или в монолите вместе с фронтендом: описываем бэкенд-часть, клиентские каталоги остаются вне набора.

Что **осознанно не входит**:

- frontend, mobile и desktop-приложения;
- инфраструктура стендов и продуктовые клиенты;
- описание UI, экранов, клиентских состояний и сборки клиента.

Это решение, а не «пока не поддержано»: набор не пытается описывать клиентские приложения и не должен обрастать их полями. В смешанном репозитории покрывается бэкенд; если бэкенда нет вовсе, проект не целевой. Доменный профиль может изменить форму бэкенда (API-only, worker, без миграций), но не превращает стартер во frontend-инструмент.

| Бэкендовое по умолчанию | Если в бэкенде этого нет |
|---|---|
| слои и направление зависимостей | модули и границы; словарь адаптируется |
| роль команды `migrate` | роль не заполняется, если миграций нет |
| владение объектами и уровни доступа | модель доступа описывается профилем |
| контракт функции «вход, выход, доступ, кто вызывает» | форма зависит от входа: HTTP, CLI или событие |

## Проверки

```text
python -m unittest discover -s tests -p "test_*.py"
python -m ai_kit.profile --check profiles/example.toml
python -m ai_kit.profile --print-schema
python -m ai_kit.templates --check
python -m ai_kit.templates --render readme --profile profiles/example.toml
python -m ai_kit.interview --check --adapter tests/fixtures/adapter/adapter.toml
python -m ai_kit.interview --plan --profile profiles/example.toml --adapter tests/fixtures/adapter/adapter.toml
python -m ai_kit.init --profile profiles/example.toml --adapter tests/fixtures/adapter/adapter.toml --dry-run
```

`doctor` проверяется корпусом `tests/conformance`; в проекте он запускается из каталога проекта: `python -m ai_kit.doctor --profile profile.toml`.

## Границы

- Правило существует только как строка реестра: номер, формулировка, метка исполнения.
- Технологии и домен — данные проекта, не канон.
- Ядро не ссылается на конкретные проекты и их документацию.
- Стартер — для бэкенд-части проекта; frontend, mobile и desktop не входят осознанно. В смешанном репозитории покрывается бэкенд, клиентские каталоги — нет. Доменный профиль меняет форму бэкенда, а не расширяет набор на клиентов.
- Существующие нарушения правил — baseline: новый код их не расширяет, затронутый участок приводится к правилу, остальное рефакторится по запросу.
