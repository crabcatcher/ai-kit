# Шаблоны документов

Шаг 4 плана. Документ описывает, как устроен шаблон, что подставляет рендерер и что проверяет валидатор. Реализация — `ai_kit/templates.py`, манифест — `documents.toml`.

## 1. Манифест

`documents.toml` перечисляет документы набора:

| Поле | Смысл |
|---|---|
| `id` | идентификатор для ссылок `{{link:id}}`; уникален |
| `template` | путь к шаблону от корня набора |
| `path` | путь результата; допускается подстановка `{docs.dir}` |
| `title` | человеческое название для отчётов и индексов |

Путь результата относителен, без `..`; других подстановок нет. Два документа не могут иметь один `id` или один путь.

## 2. Синтаксис

| Конструкция | Что делает | Если значения нет |
|---|---|---|
| `{{ путь }}` | подставляет значение профиля; список — через запятую | ошибка рендеринга |
| `{{#each путь}}...{{/each}}` | повторяет тело для каждого элемента списка | пусто |
| `{{#if путь}}...{{/if}}` | оставляет тело, если значение истинно | пусто |
| `{{ this }}` | элемент списка строк, только внутри `each` | ошибка |
| `{{link:id}}` | путь к документу из манифеста, относительно текущего | ошибка проверки |
| `{{cmd:роль}}` | команда проверки из профиля | текст «гейтов нет» |

Блоки можно вкладывать: `if` внутри `if`, `each` внутри `if` и наоборот. Внутри `each` сначала ищется поле элемента, затем — путь от корня профиля: так из строки списка доступны и `{{ name }}`, и `{{ project.name }}`.

Логические значения печатаются как «да» и «нет». Отсутствующее необязательное поле не печатается: шаблон обязан обернуть его в `{{#if}}`, иначе рендеринг остановится с ошибкой — молчаливая пустота запрещена.

Роли команд закрыты: `test`, `unit`, `e2e`, `lint`, `build`, `migrate`. Роль без команды — не ошибка шаблона, а видимый пробел: в тексте остаётся «гейтов нет».

## 3. Ссылки

`{{link:id}}` вычисляется от пути текущего документа к пути целевого, поэтому ссылки не ломаются при смене `docs.dir`. Результат всегда относительный: `./architecture.md` внутри каталога документов, `../AGENTS.md` из подкаталога.

Ссылка на документ, которого нет в манифесте, — ошибка проверки, а не текст. Это ловит переименование без правки ссылок.

## 4. Маркеры и фрагменты

Два вида маркеров:

| Маркер | Кто заполняет | Что внутри |
|---|---|---|
| `<!-- adapter:<имя>:begin -->` … `end` | адаптер или человек | факты стека, решения, карты кода |
| `<!-- generated:<имя>:begin -->` … `end` | генератор | строки реестра и списки правил |

Правила:

- маркеры остаются в результате: повторная сборка заменяет содержимое, а не ищет место заново;
- фрагмент не содержит заголовков, маркеров и подстановок — заголовки и `{{ }}` принадлежат шаблону;
- если шапка таблицы стоит вплотную перед маркером, фрагмент содержит только строки: шапка принадлежит шаблону;
- фрагмент для маркера, которого нет в шаблоне или в файле функции, — ошибка с путём;
- фрагмент, начинающийся с шапки таблицы, — ошибка, если шаблон уже дал шапку вплотную перед маркером;
- пустой `generated:`-фрагмент удаляет раздел, если в нём не осталось содержимого; пустой `adapter:`-фрагмент раздел сохраняет — видимый пробел, а не тихое удаление.

Генератор заполняет `generated:canon`, `generated:adapter`, `generated:project`, `generated:no-gate`, `generated:rules`, `generated:baseline`, `generated:features` и `generated:gaps`; источники — [generator.md](./generator.md). У `generated:incidents` и `generated:debt` источника нет: их разделы исчезают, а не заполняются догадкой. Ручное содержимое маркеров `adapter:` генератор сохраняет, если адаптер не дал нового.

Пустым считается раздел, где не осталось содержимого, кроме обычных комментариев, горизонтальной линии или таблицы без строк данных. Раздел с `adapter:`-маркером пустым не считается: он остаётся в документе, пока адаптер не даст текст. Заголовок первого уровня не удаляется никогда. Правило действует рекурсивно: опустевший подраздел удаляется, а следом может опустеть и родительский.

## 5. Комментарии шаблона

Обычный HTML-комментарий — заметка для автора шаблона, в результат он не попадает. Маркеры — тоже комментарии, но сохраняются. Поэтому примеры конструкций можно держать в шапке шаблона, не боясь, что они отрендерятся.

## 6. Проверки

`python -m ai_kit.templates --check` проверяет все шаблоны манифеста:

- блоки `each` и `if` закрыты и совпадают по типу;
- `this` не используется вне `each`;
- путь слота есть в схеме профиля, а внутри `each` — в схеме элемента;
- роль команды входит в закрытый список;
- ссылка указывает на документ манифеста;
- маркеры парные и не повторяются;
- заголовок первого уровня ровно один;
- обычные комментарии не влияют на разбор.

`python -m ai_kit.templates --render <id> --profile <путь>` печатает результат; так проверяется форма до появления генератора.

## 7. Состав набора

| id | Результат | Назначение |
|---|---|---|
| `readme` | `README.md` | обзор проекта, команды, точка входа |
| `agents` | `AGENTS.md` | представление реестра для агента |
| `docs-index` | `{docs.dir}/README.md` | индекс документов и карта правок |
| `registry` | `{docs.dir}/registry.md` | правила K/A/P и метки |
| `pipeline` | `{docs.dir}/pipeline.md` | маршрут задачи, уровни, возвраты |
| `development` | `{docs.dir}/development.md` | окружение, ветки, изменения, история |
| `architecture` | `{docs.dir}/architecture.md` | назначение, границы, слои, решения |
| `patterns` | `{docs.dir}/patterns.md` | договорённости кода |
| `security` | `{docs.dir}/security.md` | доступы, владение, секреты |
| `review` | `{docs.dir}/review.md` | порядок ревью и блокеры |
| `features-index` | `{docs.dir}/FEATURES.md` | карта функциональности |
| `tech-debt` | `{docs.dir}/tech-debt.md` | отложенное с триггером |
| `incidents` | `{docs.dir}/incidents.md` | журнал сбоев агента |
| `post-init` | `{docs.dir}/post-init.md` | план дозаполнения по майлстоунам |
| `plan` | `{docs.dir}/templates/plan.md` | шаблон плана для копирования |
| `review-report` | `{docs.dir}/templates/review-report.md` | шаблон отчёта ревью |
| `feature` | `{docs.dir}/templates/feature.md` | шаблон файла функции |

Документы процесса — `pipeline`, `review`, `development` — задают маршрут и артефакты. Шаблоны в `templates/` не являются готовыми документами: они копируются под конкретную задачу или функцию.

В файле функции первая колонка «Контрактов» — `id` входа из `inputs` профиля. `doctor` ищет покрытие именно там; без этого вход считается непокрытым. Файл создаётся вручную; `docs_fragments` с `target = "features/<имя>.md"` заполняют только adapter-маркеры.

В `architecture` раздел «Что не разобрано» собирает `unknowns` и `not_applicable`: неизвестное поле идёт с вопросом, осознанно неприменимое — с причиной. Решение остаётся видимым, даже когда раздела по этому полю в документе нет.

## 8. Как добавить шаблон

1. добавить запись в `documents.toml` с новым `id`;
2. написать шаблон: один заголовок первого уровня, разделы, маркеры для внешнего содержимого;
3. сослаться на него через `{{link:id}}` там, где он нужен;
4. прогнать `--check` и тесты.

Шаблон без манифеста не рендерится и не проверяется; документ без шаблона в манифест не попадает.
