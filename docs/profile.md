# Профиль проекта

Профиль — единственный источник фактов о проекте. Схема написана кодом (`ai_kit/profile.py`), поэтому валидатор и схема не могут разойтись: это один модуль.

Схема оптимизирована под бэкенд-разработку. Слои и зависимости, роль команды `migrate`, владение объектами и уровни доступа — форма по умолчанию. Для другого типа проекта нужен доменный профиль, а не подгонка текущей схемы.

`docs.dir` задаёт каталог документов. Для новых проектов рекомендуется `.ai`: он отделяет документы агента от публичного `docs/`. `.agent` не используем — это читается как конфигурация агента. Скрытый каталог хуже виден, поэтому ссылки из `README.md` и `AGENTS.md` обязательны.

Стек — это язык, фреймворки, хранилища и инструменты. Операционная система, версия интерпретатора агента, локальные пути и окружение машины в стек не входят: проект переносимый.

## Команды

```text
python -m ai_kit.profile --check profiles/example.toml
python -m ai_kit.profile --print-schema > profile.schema.json
python -m unittest discover -s tests -p "test_*.py"
```

## Поля

| Поле | Обязательно | Что содержит |
|---|---|---|
| `schema_version` | да | версия формата профиля |
| `project.name` | да | имя проекта |
| `project.purpose` | да | зачем проект существует |
| `project.boundaries` | да | что в проект **не** входит |
| `docs.language` | да | язык документов |
| `docs.dir` | да | каталог документов; `.project` по умолчанию, `.ai` рекомендуется для новых проектов |
| `stack.runtime`, `stack.frameworks`, `stack.stores`, `stack.tools` | нет | факты о стеке с провенансом |
| `layout.source_roots` | да | где лежит исходный код |
| `layout.layers` | нет | слои: имя, ответственность, разрешённые зависимости |
| `tests.framework`, `tests.commands` | нет | чем и как запускаются проверки |
| `process.branches` | нет | схема веток |
| `process.review_roles` | да | кто исполняет критику и ревью |
| `process.tiers` | да | включены ли уровни задачи |
| `automation.clients` | нет | клиенты агента |
| `automation.ci` | нет | система непрерывной проверки |
| `automation.pre_commit` | да | есть ли проверка перед коммитом; профиль без поля не принимается — в старом профиле добавьте `pre_commit = false` |
| `security.access_levels` | да | уровни доступа |
| `security.secrets_policy` | нет | правило обращения с секретами |
| `rules[]` | нет | правила проекта P: номер, формулировка, метка, исполнитель, кто ловит, владелец, триггер |
| `gates.disabled[]` | нет | отключённые гейты: причина, владелец, триггер |
| `unknowns[]` | нет | что осталось неизвестным и каким вопросом закрывается |
| `not_applicable[]` | нет | поля, которые осознанно неприменимы: поле и причина |
| `adapter.id` | нет | идентификатор подключённого адаптера |

## Провенанс

Каждый факт о стеке несёт provenance:

| Значение | Смысл |
|---|---|
| `probe` | найдено в файле проекта; обязателен путь-доказательство |
| `answer` | сказал человек; версия в таком факте запрещена |
| `unknown` | факта нет — запись не создаётся, вопрос уходит в `unknowns` |

**Правило версий.** Поле `version` заполняется только при `provenance = "probe"` и непустом `evidence`. Версия, названная человеком по памяти, — это `unknown` с вопросом, а не факт.

## Правила проекта

`rules` — строки пространства P, которые генератор выводит в реестр и в `AGENTS.md`. Номер начинается с `P`, метка — из закрытого списка (`гейт`, `гейт частичный`, `измеритель`, `дисциплина`, `нет гейта`, `справочник`). У гейта есть исполнитель, у дисциплины и измерителя — тот, кто ловит. Для «нет гейта» нужны причина и наблюдаемый триггер; «—» вместо триггера — ошибка. Полный список полей — `ai_kit/rules.py`.

## Ошибки

Валидатор возвращает пары «путь поля → сообщение», например `stack.runtime[0].version: версия заполняется только из probe с доказательством`. Номера строк нет: парсер не даёт позиций для семантических ошибок, и имитировать точность не нужно.

## Пример и корпус

- `profiles/example.toml` — форма профиля на вымышленном стеке; реальных технологий не содержит.
- `tests/test_profile.py` — корпус: валидный пример и поломки (версия из `answer`, отсутствующее доказательство, неизвестное поле, гейт без триггера, пустые границы, повтор слоя) плюс тест «схема покрывает все поля датаклассов».
