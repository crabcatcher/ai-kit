# Валидатор doctor

Шаг 7 плана. `doctor` отвечает на вопрос: набор собран правильно, правила исполнимы, а что не исполняется — заявлено пробелом. Реализация — `ai_kit/doctor.py`, форма отчёта — `ai_kit/diagnostics.py`, внешние гейты — `ai_kit/gates.py`.

## 1. Что проверяется

Три уровня результата:

| Уровень | Значит | Влияет на код возврата |
|---|---|---|
| ошибка | набор сломан: проверка не пройдена | да, код `1` |
| предупреждение | формально проходит, но требует внимания | нет |
| пробел | проверка не выполнена и это заявлено: нет инструмента, заглушка | нет |

Пробел — не успех. Отчёт всегда печатает число пробелов, чтобы «всё зелёное» нельзя было получить молчанием.

Doctor только читает. Он не правит документы, не устанавливает инструменты, не запускает миграции и не ходит в сеть.

## 2. Встроенные проверки

| Код | Что проверяется |
|---|---|
| `manifest` | манифест документов читается |
| `profile` | профиль проходит схему: поля, провенанс, правила |
| `adapter` | файл адаптера читается |
| `template` | шаблоны: блоки, слоты, роли команд, ссылки, маркеры, один H1 |
| `document` | документ есть по ожидаемому пути и содержит ровно один H1 |
| `placeholder` | в результате не осталось `{{ … }}` |
| `link` | относительная ссылка ведёт на существующий файл внутри проекта |
| `marker` | маркеры в готовом документе парные и не повторяются |
| `section` | пустой раздел — предупреждение, а не ошибка |
| `registry` | строки канона, адаптера и профиля попали в реестр; отключённый гейт попал в техдолг; у гейта есть строка с его инвариантом |
| `baseline` | `baseline.toml`: известные правила, владельцы, триггеры, без повторов |
| `features` | карта функций: строки ведут на существующие файлы, каждый файл внесён в карту |
| `precommit` | при `pre_commit = true` есть `tools/pre-commit.py` и `tools/hooks/pre-commit` |
| `adapter` | `detect` относительный и валидный; предупреждение, если ни одна маска не находит файл |

Источник истины для `registry` — канон, `rules` адаптера и `rules` профиля. Отрендеренный реестр сверяется с ними как артефакт: расхождение означает устаревшую генерацию, а не «так и надо».

Ссылки с якорем проверяются по файлу без якоря; внешние (`http`, `https`, `mailto`, `tel`) не проверяются.

## 3. Внешние гейты

Гейт описывается в адаптере:

| Поле | Требование |
|---|---|
| `id` | уникален |
| `invariant` | формулировка, совпадающая со строкой реестра A |
| `requires` | `binary` и необязательный диапазон `version` |
| `command` | список аргументов или строка; поддерживается подстановка `{project}` |
| `on_unavailable` | только `gap` |

`{config}` не поддерживается: модели конфигурации гейта пока нет, поэтому такая команда — ошибка, а не молчаливая подстановка.

Порядок:

1. бинарь проверяется запуском с `--version`; нет бинаря, версия не определена или не входит в диапазон — пробел;
2. команда запускается в каталоге проекта с таймаутом 120 секунд, без shell;
3. код `0` — чисто, `1` — нарушение, `2` — ошибка конфигурации, `3` — не реализовано, остальное — неожиданный код;
4. `3` даёт пробел; если строка реестра при этом помечена «гейт» или «гейт частичный», добавляется ошибка: гейт заявлен, но его нет.

По умолчанию внешние команды не запускаются: нужен `--gates`. Без него отчёт содержит предупреждение, что гейты не запускались.

Диапазон версий — подмножество: `>=`, `>`, `<=`, `<`, `==`, несколько условий через пробел (`>=1.0 <2.0`). Версия берётся из первого числа в выводе `--version`.

## 4. Отчёт и коды возврата

Человеческий отчёт — таблица «уровень, код, место, сообщение» и строка с числами. `--json` печатает то же машинно:

```json
{
  "summary": {"errors": 0, "warnings": 1, "gaps": 1},
  "diagnostics": [
    {"code": "gate", "severity": "gap", "path": "layers", "message": "…"}
  ]
}
```

Коды возврата: `0` — ошибок нет (предупреждения и пробелы допустимы), `1` — есть ошибки, `2` — ошибка использования.

## 5. Конформанс-корпус

Корпус — приёмочный набор: каждая фикстура содержит один известный дефект и ожидаемый диагноз. Он лежит в `tests/conformance/cases/<имя>/`.

| Файл | Что содержит |
|---|---|
| `case.json` | адаптер, флаг гейтов, мутации, ожидаемые диагнозы, код возврата |
| `adapter.toml` | адаптер фикстуры, если нужен; `@PYTHON@` заменяется на путь интерпретатора |
| `profile.toml` | базовый профиль, если нужен; иначе берётся пример набора |

`case.json` применяется так: проект генерируется штатным `init`, затем выполняются мутации (`delete`, `append`, `write`, `replace`), затем запускается `doctor`. Ожидание — подмножество диагнозов: код, уровень, часть пути и часть сообщения. Код возврата сверяется точно.

Состав корпуса:

| Фикстура | Что проверяет |
|---|---|
| `clean` | собранный проект без дефектов |
| `broken-link` | ссылка в никуда |
| `leftover-placeholder` | остаток `{{ }}` |
| `empty-section` | пустой раздел как предупреждение |
| `missing-document` | документа нет по пути |
| `stale-registry` | строка канона пропала из реестра |
| `debt-row-missing` | отключённый гейт пропал из техдолга |
| `profile-no-gate-trigger` | «нет гейта» без причины и триггера |
| `gate-without-rule` | гейт без строки реестра |
| `gate-unavailable` | бинарь недоступен — пробел |
| `gate-stub` | код `3` — пробел и расхождение реестра |
| `gate-violation` | код `1` — нарушение |
| `gate-config-error` | код `2` — ошибка конфигурации |
| `gate-not-run` | гейты не запускались без `--gates` |

Условие приёмки шага — 100% корпуса. Это же условие перехода на единую реализацию проверки документов: пока корпус не зелёный, старая реализация не заменяется.

## 6. Команды

```text
python -m ai_kit.doctor --profile profile.toml
python -m ai_kit.doctor --profile profile.toml --adapter adapter.toml --gates
python -m ai_kit.doctor --profile profile.toml --json
python -m unittest discover -s tests -p "test_*.py"
```

Запуск — из каталога проекта; набор должен быть доступен интерпретатору.

## 7. Как добавить проверку

1. выбрать код и уровень: ошибка — только если нарушение детерминировано;
2. вернуть `Diagnostic(code, severity, path, message)`, а не печатать;
3. добавить фикстуру в корпус: дефект и ожидаемый диагноз;
4. прогнать корпус и юнит-тесты.

Проверка, которую нельзя воспроизвести фикстурой, в корпус не попадает и считается незавершённой.

## 8. Границы шага

- внешние гейты не реализуются набором: только запуск и чтение кода;
- `{config}` и другие подстановки, кроме `{project}`, не поддерживаются;
- проверка стиля и содержания документов остаётся человеку и ревью;
- вопрос зрелости проекта не решается: `doctor` одинаково проверяет собранный набор независимо от того, новый проект или развивающийся;
- автоправок нет: `doctor` не меняет файлы.
